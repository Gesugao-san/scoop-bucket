# scoop-bucket

[![CI](https://github.com/Gesugao-san/scoop-bucket/actions/workflows/ci.yml/badge.svg)](https://github.com/Gesugao-san/scoop-bucket/actions/workflows/ci.yml) [![Excavator](https://github.com/Gesugao-san/scoop-bucket/actions/workflows/excavator.yml/badge.svg)](https://github.com/Gesugao-san/scoop-bucket/actions/workflows/excavator.yml)

Personal [Scoop](https://scoop.sh) bucket by [Gesugao-san](https://github.com/Gesugao-san).

## Usage

```powershell
scoop bucket add gesu https://github.com/Gesugao-san/scoop-bucket
scoop install gesu/NBT-Studio
scoop install gesu/NBT-Explorer
scoop install gesu/iloader
scoop install gesu/Apple-Mobile-Drivers-Installer
scoop install gesu/Privoxy
scoop install -g gesu/NetTime   # global, from an elevated shell
scoop install gesu/Freesm-Launcher
scoop install gesu/Radmin-VPN
scoop install gesu/Samsung-Magician
scoop install gesu/PlanetSide-2             # through Steam
scoop install gesu/PlanetSide-2-LaunchPad   # standalone, elevated shell
scoop install gesu/Tixati
scoop install gesu/Fopnu
scoop install gesu/DarkMX
scoop install gesu/WinMX                    # setup wizard, elevated shell
scoop install gesu/DriverStore-Explorer     # runs elevated (UAC prompt)
scoop install gesu/OCCT                     # runs elevated (UAC prompt)
scoop install gesu/TrueConf
scoop install gesu/Ghidra                   # needs JDK 25
scoop install gesu/x64dbg
scoop install gesu/Bulk-Crap-Uninstaller    # runs elevated (UAC prompt)
scoop install gesu/UltraDefrag              # runs elevated (UAC prompt)
scoop install gesu/JkDefrag                 # runs elevated (UAC prompt)
```

`gesu` is only a local name for the bucket; any other name works too.

Works in [UniGetUI](https://github.com/Devolutions/UniGetUI) too: add the bucket in UniGetUI's Scoop settings (or with the command above), then search for the package.

Some antivirus programs flag compiled AutoIt scripts. No `checkver`: nothing new is expected. License: GPL v2 or later (source headers). Not in the [Extras](https://github.com/ScoopInstaller/Extras) bucket. |

Non-portable packages (`NetTime`, `Radmin-VPN`, `Samsung-Magician`, `PlanetSide-2-LaunchPad`, `WinMX`) check before installing whether the program is already installed on the system without Scoop, and stop instead of silently taking it over (a later `scoop uninstall` would remove that copy too). `scoop update` is not affected. For `Radmin-VPN`, `Samsung-Magician`, `PlanetSide-2-LaunchPad` and `WinMX`, whose installers can install over an existing copy, run `$env:GESU_ALLOW_EXISTING = '1'` in the same shell to let Scoop take over; the variable stays set until you close the shell or run `Remove-Item Env:GESU_ALLOW_EXISTING`. `NetTime` has no such override: its regular installer registers its own `NetTimeSvc`, which a Scoop copy cannot share.

Scoop puts shortcuts only for files inside its app folder, so `Radmin-VPN`, `Samsung-Magician`, `PlanetSide-2-LaunchPad` and `WinMX` find the folder the installer used (through the program's uninstall entry) and link it into the app folder as a junction (`RadminVPN`, `SamsungMagician`, `LaunchPad`, `Winmx`); the shortcut in *Scoop Apps* points through it. Update and uninstall delete only the junction, before Scoop touches the app folder, never the files it points to. If the program is not found where its uninstall entry says, Scoop warns and installs without the shortcut. To get the shortcut for a copy installed before it was added, run `scoop update -f <package>` from an elevated shell: it reruns the installer over the existing copy.

`Tixati`, `Fopnu`, `DarkMX` and `WinMX` stop if the program is running or its data files are open in another program (the program itself, a backup or sync tool). Scoop's own check only looks for processes started from the app's folder in `~\scoop\apps`; [`scripts/common/Test-AppBusy.ps1`](scripts/common/Test-AppBusy.ps1) also finds copies started from anywhere else, by process name, and tries to open every file in the data folder (`%APPDATA%\tixati`, `%APPDATA%\fopnu`, `%APPDATA%\darkmx`, the WinMX folder) exclusively. A fresh install is checked in `pre_install`; `scoop update` and `scoop uninstall` are checked in `pre_uninstall`, because Scoop runs that hook before it removes anything, while `pre_install` of the new version only runs after the old one is gone. Scoop runs the `pre_uninstall` of the manifest saved at install time, so the update check starts working once a version with it is installed (`scoop update <app> -f` does that). If the helper is missing, for example after `scoop bucket rm gesu`, the uninstall check only warns, so the app can still be removed.

Manifest names keep the product's capitalisation: UniGetUI builds the display name from the file name with [`FormatAsName`](https://github.com/Devolutions/UniGetUI/blob/b85288414fea52a1283a67599da5558d4818d606/src/UniGetUI.Core.Tools/Tools.cs#L320), which turns dashes into spaces and only upper-cases the first letter of each word (`NBT-Studio` → "NBT Studio", but `nbt-studio` → "Nbt Studio"). Scoop itself is case-insensitive, so `nbt-studio` works in commands too. Folders under `scripts/` are lowercase; they do not affect the display name.

## Installing from a mirror

Scoop has no fallback URLs: an array in `url` lists different files, not alternatives for one file, and a failed download stops the install. It does look in its cache first, though, so [`bin/Use-Mirror.ps1`](bin/Use-Mirror.ps1) downloads the file from another host into the cache under the name Scoop expects for the manifest URL:

```powershell
.\bin\Use-Mirror.ps1 gesu/TrueConf            # list TrueConf's mirrors
.\bin\Use-Mirror.ps1 gesu/TrueConf mirror1    # first mirror; or by name: trueconf.ru
scoop install gesu/TrueConf
```

Known mirrors are kept in [`mirrors.psd1`](mirrors.psd1), a PowerShell data file read with `Import-PowerShellDataFile`, which accepts data only, so the file cannot run code. It is not JSON on purpose: in CI, Scoop's tests check every changed `*.json` file in the repository against the manifest schema, not only those in `bucket/`. Each app has a list of mirrors; `mirror1`, `mirror2`, ... pick them by position, and each one's `name` works too. A mirror gives one URL per architecture (`64bit`, `32bit`, `arm64`), or `url` for apps without architectures; any of them can be an array when the manifest downloads several files, and `$version` in a URL is replaced with the manifest's version. A full URL instead of a mirror name works for hosts not in the file:

```powershell
.\bin\Use-Mirror.ps1 gesu/TrueConf https://download.trueconf.ru/download/client/windows/trueconf_client_x64.msi
```

Run it from a clone of this repository or from the copy Scoop keeps of the bucket, `~\scoop\buckets\gesu` (under `$env:SCOOP` if Scoop lives elsewhere). The script loads Scoop's own `lib/` to find the manifest, the cache folder (`SCOOP_CACHE` and `cache_path` included) and the cache file name, so it follows whatever the installed Scoop does. It checks the downloaded file against the manifest's hash before putting it into the cache, so a mirror can only supply the exact file the manifest describes, and Scoop checks the hash again when it installs. `-Architecture` picks another architecture, `-Index` another file when a manifest lists several. The manifest URL is part of the cache file name, so each new version needs a new run.

## Automation

GitHub Actions from Scoop's [BucketTemplate](https://github.com/ScoopInstaller/BucketTemplate), using [ScoopInstaller/GithubActions](https://github.com/ScoopInstaller/GithubActions):

| Workflow | Runs | Does |
|---|---|---|
| [`excavator.yml`](.github/workflows/excavator.yml) | every 4 hours, or by hand ([see below](#running-workflows-by-hand)) | Runs `checkver` with autoupdate on every manifest and pushes new versions with their hashes straight to `main`, as `github-actions[bot]`. A second job, *Check TLS*, runs [`bin/Test-Tls.ps1`](bin/Test-Tls.ps1) ([see below](#checking-tls)) |
| [`ci.yml`](.github/workflows/ci.yml) | every push and PR | Scoop's Pester tests in Windows PowerShell and PowerShell 7: manifest schema and file style |
| [`issues.yml`](.github/workflows/issues.yml) | new issues | Checks reports such as `app@1.2.3: hash check failed` and fixes the hash if it really changed |
| [`pull_request.yml`](.github/workflows/pull_request.yml) | new PRs, `/verify` comments | Checks the changed manifests and posts the results |

Notes:

- The tests run on `bucket/` only ([`Scoop-Bucket.Tests.ps1`](Scoop-Bucket.Tests.ps1)): Scoop's style tests read every file as text and would fail on the PNGs in `icons/` and `screenshots/`. The schema check is wider in CI: it takes every changed `*.json` in the repository, so JSON files that are not manifests must not be added anywhere.
- Manifests use Scoop's own format (4-space JSON) because Excavator rewrites a manifest with Scoop's formatter whenever it updates it. Run `.\bin\formatjson.ps1` after editing by hand.
- `.gitattributes` gives text files CRLF in working copies, which the tests require; the repository itself stores LF.
- GitHub turns off scheduled workflows in public repositories after 60 days without activity; re-enable Excavator on the Actions tab if that happens.
- [`bin/`](bin) holds `Use-Mirror.ps1` ([see above](#installing-from-a-mirror)), `Test-Tls.ps1` ([see below](#checking-tls)) and the usual helper wrappers (`checkver.ps1`, `checkurls.ps1`, `checkhashes.ps1`, `formatjson.ps1`, `missing-checkver.ps1`, `auto-pr.ps1`, `test.ps1`) for running Scoop's maintainer scripts against this bucket locally.

### Running workflows by hand

Excavator and CI can be started from the [Actions tab](https://github.com/Gesugao-san/scoop-bucket/actions) (pick the workflow, then **Run workflow**) or with the [GitHub CLI](https://cli.github.com/):

```powershell
gh workflow run excavator.yml -R Gesugao-san/scoop-bucket
gh workflow run excavator.yml -R Gesugao-san/scoop-bucket -f force=NetTime,Privoxy
gh workflow run ci.yml -R Gesugao-san/scoop-bucket
gh run watch -R Gesugao-san/scoop-bucket
```

`force` lists manifests that Excavator re-downloads and re-hashes even when the version is unchanged, for when upstream replaces a file without a new version number. The issue and PR handlers have no manual run: they need the issue or PR that triggered them.

### Checking TLS

[`bin/Test-Tls.ps1`](bin/Test-Tls.ps1) collects every host the manifests use (homepage, downloads, `checkver`, `autoupdate`) and the mirrors in `mirrors.psd1`, and opens a TLS handshake to each one through Schannel, the same TLS stack Scoop downloads with. It sends no HTTP request and does not check revocation.

| Status | Means |
|---|---|
| `FAIL` | no TCP connection, no TLS handshake, an expired certificate, or one Windows does not trust |
| `WARN` | plain HTTP, TLS older than 1.2, or a certificate that expires within 21 days (`-WarnDays`) |
| `OK` | everything else |

Excavator runs it as a separate job, *Check TLS*, every 4 hours: the table goes to the run summary, failures and warnings appear as annotations, and the job turns red when a host fails (Excavate itself is not affected). A GitHub runner is outside Russia, so comparing with a run on your own PC tells where a problem is: a host that fails on both is broken on its own side; a host that fails only at home is blocked or filtered on the way.

```powershell
.\bin\Test-Tls.ps1                                  # all hosts, as a table
.\bin\Test-Tls.ps1 TrueConf, Radmin-VPN | Format-List  # these apps only, all details
```

## File associations

Like the [`git` manifest](https://github.com/ScoopInstaller/Main/blob/bcff7c46a4ad0a7765b9f61260ab75440a3e69ea/bucket/git.json) in Scoop's [Main bucket](https://github.com/ScoopInstaller/Main), `NBT-Studio` ships [registry templates](scripts/nbt-studio) instead of touching the registry on its own. `post_install` fills in the install path; after install, run:

```cmd
reg import "%USERPROFILE%\scoop\apps\NBT-Studio\current\install-associations.reg"
```

This makes NBT Studio the default app for `.nbt` and adds it to "Open with" for `.snbt`, `.dat`, `.dat_old`, `.mca`, `.mcr`, `.mcc`, `.mcstructure` and `.schematic` without changing their defaults. Paths point to `current`, so they survive updates. `scoop uninstall` imports [`uninstall-associations.reg`](scripts/nbt-studio/uninstall-associations.reg) and removes the entries.

### Icon size in UniGetUI

Checked against UniGetUI's source at commit [`b852884`](https://github.com/Devolutions/UniGetUI/tree/b85288414fea52a1283a67599da5558d4818d606):

- **Pixel size: 192 × 192 at most in practice.** After download, [`DownsizeImage`](https://github.com/Devolutions/UniGetUI/blob/b85288414fea52a1283a67599da5558d4818d606/src/UniGetUI.Core.IconStore/IconCacheEngine.cs#L318) shrinks any PNG, WebP, TIFF or AVIF icon whose side exceeds [`MAX_SIDE = 192`](https://github.com/Devolutions/UniGetUI/blob/b85288414fea52a1283a67599da5558d4818d606/src/UniGetUI.Core.IconStore/IconCacheEngine.cs#L322), keeping the aspect ratio. A non-integer downscale blurs pixel art, which is why the 192 px versions here exist: 192 = 16 × 12.
- **File size: no limit in the code.** Icons are fetched with a plain [`HttpClient`](https://github.com/Devolutions/UniGetUI/blob/b85288414fea52a1283a67599da5558d4818d606/src/UniGetUI.Core.IconStore/IconCacheEngine.cs#L236) using .NET defaults: a [100 s timeout](https://learn.microsoft.com/dotnet/api/system.net.http.httpclient.timeout) and the whole body read into memory. Keep icons small anyway; they are re-downloaded whenever the cache is cleared.
- **Formats** are chosen by the server's `Content-Type` ([mapping](https://github.com/Devolutions/UniGetUI/blob/b85288414fea52a1283a67599da5558d4818d606/src/UniGetUI.Core.IconStore/IconCacheEngine.cs#L464)): PNG, WebP, AVIF, GIF, SVG, ICO, TIFF. JPEG and BMP are commented out as non-transparent, so such icons are not loaded at all.
- **Shape:** the [contribution guide](https://www.marticliment.com/unigetui/help/icons-and-screenshots) asks for a square PNG.
- **Lookup key:** [`GenerateIconId`](https://github.com/Devolutions/UniGetUI/blob/b85288414fea52a1283a67599da5558d4818d606/src/UniGetUI.PackageEngine.PackageManagerClasses/Packages/Package.cs#L451) lower-cases the package ID and turns `_ . space / ,` into dashes, so the icon is found under `nbt-studio` whatever the case of the manifest name.
- **Adding an icon:** the old Google Sheet is closed; icons now go in through pull requests to [`screenshot-database-v2.json`](https://github.com/Devolutions/UniGetUI/blob/main/WebBasedData/screenshot-database-v2.json) (see the [file's history](https://github.com/Devolutions/UniGetUI/commits/main/WebBasedData/screenshot-database-v2.json) for examples).
