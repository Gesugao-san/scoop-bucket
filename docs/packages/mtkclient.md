# MTKClient

| | |
|---|---|
| Manifest | [`bucket/MTKClient.json`](../../bucket/MTKClient.json) |
| Upstream | [bkerler/mtkclient](https://github.com/bkerler/mtkclient) |
| Install | `scoop install gesu/MTKClient                # builds with uv, needs internet` |

MTKClient: reads and writes the flash of MediaTek phones and boards over BROM, preloader and DA, unlocks the bootloader (`da seccfg unlock`), dumps keys and RPMB. Commands `mtk`, `mtk_gui`, `mtk_stage2`, `mtk_da_parser`, `mtk_brom_to_offs`; *MTKClient* shortcut in Scoop Apps for the GUI. **Tracks `main`, not releases**: the last release, v2.1.4.1, is from 18 March 2026, and `main` has since gained a safer `seccfg` unlock (the old one bricked some devices; `--critical` brings it back) and Windows USB fixes (bundled libusb, fallback to UsbDk on *Access denied*). The version is the last release tag plus the UTC time of the newest commit on `main` (`2.1.4.1-20261026.0853`), and the URL is pinned to that commit; `checkver` asks the GitHub API for both. There is no Windows build, so the installer runs [`uv`](https://github.com/astral-sh/uv) (a dependency): `uv sync --frozen --no-editable` builds the source and installs the dependency versions pinned in upstream's `uv.lock` into `venv` in the app folder, on a private CPython 3.14 that uv downloads into the same folder, so updates of Scoop's `python` cannot break it (uv is told not to add it to the `PATH` or the registry). That Python is x64 also on ARM64 Windows (emulated), because the bundled `libusb-1.0.dll` is x64 only; there is no 32-bit package, PySide6 has no 32-bit build. Install therefore needs internet access to PyPI and to GitHub (python-build-standalone). USB: Windows gives MediaTek's BROM/preloader port (`VID_0E8D`) a serial driver that libusb cannot open, so bind WinUSB to it with [`Zadig`](../../bucket/Zadig.json) or install [`UsbDk`](../../bucket/UsbDk.json), which keeps the serial driver; the manifest suggests both. `mtk fs` needs the WinFsp driver: the manifest suggests `nonportable/winfsp-np`. mtkclient writes `logs` (`log.txt` and the per-device hwparam keys) into the current folder: the shortcut starts the GUI in `venv\Scripts`, where `logs` is persisted; `mtk` from a console writes into the console's folder. [`MTKClient-Release`](../../bucket/MTKClient-Release.json) is the same package on the latest release instead; both add the same commands, so only one can be installed (`pre_install` stops otherwise). Not in Scoop's official buckets.
